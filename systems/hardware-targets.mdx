## Overview

THRINDEX separates the portable model from the chip. `thx.compile` writes a `.thx` with target `sim`. The Console turns that file into the AKD1500 program when you deploy. The Runtime on the device loads that program. The SDK does not talk to the chip.

```
Developer machine              Console                         Device
─────────────────              ───────                         ──────
thx.compile → model.thx   →    Deploy to the device      →    Runtime loads the program
                               (uses the device chip type)
```

Inputs stay on the device. The Console does not receive them.

## BrainChip AKD1500

AKD1500 is a chip. The SDK does not compile a `.thx` for it. This is the compile that works:

```python
import thrindex as thx

thx.compile(model, "model.thx")
```

`thx.compile(..., target="akida-akd1500")` fails. The compiler accepts `sim` only. At deploy, the Console uses the device chip type and builds the chip program. The artifact's target field is not that program.

`akida-akd1500` below is the name of the local backend and of the conformance exclusion. It is not a `thx.compile` target.

### Capability

| Field | Value |
|---|---|
| Backend name | `akida-akd1500` |
| Native timestep | 1.0 ms |
| Native delay support | None (`native_delay_max_steps = 0`) |
| Delay fallback | Reject |
| Precision | 4-bit integer per tensor |
| Weight range | `[-7, 7]` (int8 container, 4-bit values) |

### What the AKD1500 supports

AKD1500 executes feedforward integer networks.

- **Dense** (`snn.Dense`) — fully connected, no delays. Pass `bias=False`. A non-zero bias is rejected (E0406) because this chip program has no bias input. A bias of all zeros is accepted. The default `bias=True` is not zero after training.
- **Conv2d** (`snn.Conv2d`) — kernel 3, 5, or 7, image at least 5×5. Pass `input_height` and `input_width`; the layer does not store the image size.

A LIF layer is rejected. This chip has no membrane, so it cannot leak, integrate, or reset.

### What the AKD1500 rejects

| Condition | Error |
|---|---|
| LIF layer in artifact | [E0401](/errors/E0401) |
| Synaptic delays in artifact | [E0402](/errors/E0402) |
| Non-finite (NaN / Inf) weights | [E0403](/errors/E0403) |
| Artifact compiled for a different target | [E0404](/errors/E0404) |
| Input with more than one timestep (`T > 1`) | [E0407](/errors/E0407) |

AKD1500 is not an SNN backend. It does not implement leaky integrate-and-fire dynamics, temporal state, or spike-triggered reset. If your model uses LIF neurons, use `target="sim"` instead. See [E0401](/errors/E0401) for a full explanation.

### Weight quantization

Weights are quantized from `f32` to 4-bit signed integers during the Tier-1 compile step:

```
scale = max(|W|) / 7
W_int = round(W / scale)  — clamped to [-7, 7]
```

The quantization error is at most `scale / 2` per weight. For models with large weight ranges, this error can be significant. Training with weight regularization that keeps `max(|W|)` small reduces quantization error.

## Put a model on the chip

1. Compile a dense model. `sim` is the only compile target:

```python
import thrindex as thx
import thrindex.snn as snn

model = snn.Sequential(
    snn.Dense(4, 2, bias=False),
)
thx.compile(model, "model.thx")
```

`bias=False` is required. `snn.Dense` otherwise adds a bias, and the deploy is rejected rather than omitting it.

A model with a LIF layer is rejected for this chip. A convolution passes the image size on the first layer:

```python
snn.Conv2d(1, 1, kernel_size=3, padding=1, bias=False, input_height=5, input_width=5)
```

2. In the Console, open **Devices → Connect a device**. Copy **Install** onto the machine that has the chip. The first time, also copy the Console key and run `sudo thrindex-runtime setup`. Setup prints a fingerprint. Use **Add device**, choose BrainChip AKD1500, and paste that fingerprint. When the device is already connected, run Install and `sudo systemctl restart thrindex-runtime`. Do not run setup again.

3. Upload `model.thx` under **Artifacts**. Open it, choose the device, and press **Deploy to device**. Wait until the deployment is **Confirmed**. Confirmed means the program is on the chip. The chip computes when something on the device sends an input.

## Send an input

Software on the device sends one input and reads the floats back. The reference client is the Runtime CLI. It does not open the chip itself. The values never go to the Console.

```sh
printf '0.1 0.2 0.3 0.4\n' | thrindex-runtime infer
```

The input is whitespace-separated floats, one sample. A dense model wants as many values as `in_features`. A convolution wants `input_height × input_width × in_channels` in row-major order, the last channel index changing fastest. Each output float is printed on its own line.

A 5×5 center-tap convolution (kernel 3×3, only the center weight is 1, padding 1) copies each pixel with the same 4-bit rounding as the dense layer. Put `0.2` at the center, index 12. The other 24 values are `0`. The center line is `0.2`. The other lines are `0`.

```sh
python3 -c 'v=[0.0]*25; v[12]=0.2; print(*v)' | sudo thrindex-runtime infer
```

The socket is `/run/thrindex/infer.sock`, group `thrindex`, mode `0660`. A process in that group can connect. Otherwise use `sudo`. Add a user with `sudo usermod -aG thrindex <user>`.

The frame is little-endian. A request is `THXI`, version `u16` = 1, flags `u16` = 0, count `u32`, then that many `f32`s. A response is `THXO`, version `u16` = 1, status `u16`, count `u32`, then the payload. Status `0` is that many floats. Status `1` is UTF-8, at most 400 bytes. More than 8192 floats is rejected.

AKD1500 inputs are 4-bit and unsigned. Float `0` stays `0`. Float `1` is the top code. A value above `1` saturates. A value below `0` becomes `0`. The float that comes back can differ from the simulator by one 4-bit step. For a layer that copies its input, `0.1` comes back as `0.13333334` and `0.2` comes back as `0.2`.

## Conformance

`akida-akd1500` is **permanently excluded** from the THRINDEX Certified [v0] conformance suite. The Certified badge measures spike-raster equivalence between a hardware backend and the reference simulator. AKD1500 does not implement SNN dynamics — it performs integer feedforward inference — and cannot produce a spike raster that is equivalent to the LIF simulator output.

When the conformance harness runs, it prints:

```
EXCLUDED akida-akd1500: reason=non-snn-backend; metric=top-1-accuracy-frozen-brainchip-dataset
```

The alternative metric (top-1 accuracy on the frozen BrainChip dataset) is the appropriate correctness measure for AKD1500 inference. See [Conformance Overview](/conformance/overview) for details.
