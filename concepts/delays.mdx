title: "Synaptic Delays"
description: "Integer delays on a Dense layer: what the number means, and what is stored in the .thx file."

## What a delay is

`snn.Dense(..., delay=k)` holds the incoming vector for `k` timesteps and then multiplies by the weights. `k` is the same for every connection in that layer.

`delay=0` is the default. The layer sees the vector from the current timestep. Nothing is written into the artifact.

`delay=1` means the layer sees the previous timestep, and the first timestep sees zeros. `delay=2` looks two steps back. The value has to fit in an unsigned 16-bit integer (`0` through `65535`).

The delay is not a field of `snn.LIF`. Putting it on the neuron raises `NotImplementedError`. The connection is the dense layer.

```python
import thrindex.snn as snn

model = snn.Sequential(
    snn.Dense(700, 128, delay=2),
    snn.LIF(threshold=1.0, tau_mem=10.0),
)
```

`Sequential` owns the buffer and clears it at the start of every `forward`, the same way it clears the membrane. A standard optimizer updates the weights. The delay is a fixed integer. It is not a learned parameter, and there is no delay optimizer.

Gradients still flow through the delayed value, because the stored tensor stays in the autograd graph.

## What the file stores

When `delay` is greater than 0, `thx.compile` writes one little-endian `u16` per connection, row-major `[out_features, in_features]`, in `delays_b64`, with `delays_encoding` set to `"dense"`. The simulator reads those integers and applies the same shift.

A convolution has no delay field. Delay a later dense layer if the stack needs a lag after the spatial map.

## What the simulator does

The simulator target emulates the delay with a ring of past inputs. A step that looks further back than the samples seen so far reads zero. That matches training.

A chip that cannot represent the delay rejects the artifact at its own compile step. The portable `thx.compile` call still targets the simulator.
