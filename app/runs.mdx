The **Runs** view lists every completed training run for the current project. Each run is a subdirectory under `runs/` in the project folder.

---

## Run list

The left sidebar shows all runs in reverse-chronological order. Each row shows:

- **Run ID** - the UTC timestamp in short form (`Nov 17 · 19:05`)
- **Device** - which hardware the run trained on
- **Last metrics** - accuracy from the final epoch, if available

Click a row to select the run. The main panel shows the full metrics history. The right panel shows the run manifest.

---

## Run ID

Each run is identified by its folder name - the UTC start timestamp:

```
2026-11-17T19-05-01Z
```

The app displays this as `Nov 17 · 19:05`. Hover the displayed form to see the raw folder name. You can find the folder in the **Files** view using the same name.

If two runs start within the same second, the second gets a `-2` suffix: `2026-11-17T19-05-01Z-2`.

---

## Metrics history

Selecting a run loads `metrics.jsonl` and renders:

- Confusion matrix (if the run used a held-out split)
- Spike raster from the last epoch (LIF layers only)
- Accuracy chart (training accuracy, plus held-out if available)
- Loss chart

---

## Reading the spike raster

The raster shows the spike output of each LIF layer in the network, for a single sample from the training split (the same sample is used consistently across runs for comparison).

**What to look for:**

A healthy, learning LIF layer shows a **sparse, non-uniform** spike pattern. Some neurons are active at specific timesteps, most are quiet. This is characteristic of a network that has learned to fire selectively in response to the input.

**Warning patterns:**

| Pattern | What it means |
|---|---|
| Mostly empty (all white) | The LIF layer is silent. Threshold is too high, or the upstream Dense layer is producing small activations. |
| Fully saturated (all black) | Every neuron fires at every timestep. Threshold is too low. |
| Uniform noise with no structure | The network has not learned anything. All neurons fire at similar random rates. |
| Structured but output LIF is empty | The hidden layer is learning, but the output LIF cannot fire. Lower the output threshold. |

After a successful few epochs on SHD, you should see the hidden LIF layer developing sparse structure - columns of active neurons at specific timestep ranges corresponding to the temporal features of the spoken digit.

## Reading the confusion matrix

The confusion matrix is shown when the run used a held-out split (most built-in datasets). Rows are the true class; columns are the predicted class. Values are row-normalized (each row sums to 1.0).

A well-trained model shows a bright diagonal and near-zero off-diagonal values. Common patterns in early SHD training:

- Large off-diagonal blocks in the top-left corner: the network is confusing the English digit set
- Symmetric confusion between pairs (e.g. "one" and "nine"): the network is responding to overall spike count rather than temporal structure
- One class systematically predicted for everything: the output LIF for that class fires more strongly due to initialization

## Run manifest

The manifest comes from `manifest.json` written at the end of each run.

| Field | Description |
|---|---|
| **SDK version** | THRINDEX SDK version that produced this run |
| **Device** | Hardware used (`Apple GPU`, `CPU`, etc.) |
| **Optimizer** | Always `adam` in the current version |
| **Gradient clip** | Gradient norm clipping value (always `5.0`) |
| **Split** | `train` when no test split exists, `train+test` otherwise |
| **Seed** | The encoder seed - controls weight init, shuffle order, and rate draws |

The manifest is an exact record of the training conditions. It is written only after the run completes. Combined with the project snapshot inside `manifest.json`, it contains everything needed to reproduce the run from scratch using the THRINDEX SDK.

## Simulation

Each completed run contains a `model.thx` artifact - the compiled, sealed SNN. You can run the THRINDEX behavioral simulator on it directly from the Runs view.

Click **Simulate** in the sidebar. The worker loads the artifact and runs one sample from the training split through the full forward pass in the THRINDEX behavioral simulator.

**Simulation outputs:**

| Output | Description |
|---|---|
| Prediction | Predicted class index |
| Output spike raster | Spike activity in each LIF layer during the simulated forward pass |
| Sample class | The true class of the sample being simulated |

The simulation uses the same seed as training. It is deterministic: running it twice produces the same result.

**What the simulation tells you:** simulation shows the actual computation the compiled artifact performs, independent of the training framework. It confirms the artifact matches the trained model and gives you a detailed view of the spike dynamics at inference time - which neurons fire, when, and how the output class emerges from the spike counts.

<Note>
Simulation requires a sealed run - one that completed and wrote a `model.thx` file. Runs stopped before completion do not have an artifact.
</Note>

## Run files

The **Files** view gives direct access to run contents. Navigate to `runs/` and then into the run ID directory:

```
metrics.jsonl       one JSON line per epoch: epoch, loss, trainAccuracy, heldOutAccuracy
manifest.json       training metadata and project snapshot
model.thx           compiled artifact - sealed, self-contained
preview/
  confusion.json    confusion matrix over the held-out set
  raster.json       spike raster data from the last training epoch
```

You can open `model.thx` directly in the **Files** view and run simulation from there.
